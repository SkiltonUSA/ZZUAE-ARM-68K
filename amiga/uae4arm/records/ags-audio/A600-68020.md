# A600 68020 USB boot: missing-FPU exception fix

The A600 68020 interpreter now reaches the AGS Classic ECS selector from a
read-only physical USB SD card with 2 MiB Chip and 8 MiB Fast RAM. Keep FPU off.
This is an accelerated A600 configuration, not the CPU in a stock A600.

## Two separate failures

The launcher and player originally restricted USB SD and A600 Fast RAM to the
compatible 68000. Simply removing those checks was insufficient. With memory
and transport working, the guest stopped in SetPatch with `8000000B`.

The generated 68020 handlers advance the PC before calling FPU helpers. Our
no-FPU linkage stubs called `op_illg()` at that advanced address. A software
probe therefore received an F-line exception identifying the wrong instruction.
The recovery handler could not recognise/resume the probe correctly.

The corrected stub follows the pinned UAE4ARM `fpu_op_illg` behaviour: set
`regs.fp_exception`, restore `regs.instruction_pc`, then call `op_illg()`.
It reports an absent FPU correctly; it does not execute floating-point arithmetic.
The optional VFP-backed FPU player is a separate implementation.

## Regression and hardware checks

A synthetic FRESTORE probe installs its own F-line handler, checks the stacked
PC, skips the unsupported instruction, and resumes at a marker instruction.
Before the fix the stacked PC was two bytes too far forward and the marker was
not reached. Afterward it passes in interpreter and JIT modes; the JIT test
also executes a translated ADDQ loop.

ARM instruction-model checks also cover every 64 KiB Fast RAM bank, expansion
boundaries, IDE sector transfers and read-only rejection. These checks do not
establish physical cache or device behaviour.

The corrected physical 6,000-frame A600/Paula run completed 836 USB reads,
zero writes/errors, registered 8 MiB Fast RAM in Exec, reached the selector,
and restored MMU/register state before releasing the allocation. The earlier
failed SetPatch run produced silence, so its low gap count is excluded from
audio comparisons. These are boot/selector tests, not all-game certification.

## Memory and scope

The accelerated player retains its 32 MiB executable cache. Its heap grows
from 8 to 16 MiB to accommodate guest Fast RAM, requiring 72 MiB total owned
ZZ9000 RAM. Linker, ELF packaging and MMU mapping bounds enforce that allocation.
The compatible 68000 player remains at 64 MiB. No fixed DDR address or shared
firmware memory is used.

A600 Fast RAM and USB boot are enabled for the compatible 68000 and 68020
interpreter with FPU off. JIT/Cyclone Fast RAM and A1200 physical USB boot remain
restricted pending separate validation. File-HDF support is unchanged.
