# Independent AGA bitplane-fetch validation

This adds a correctness gate for future A1200 optimisation. The diagnostic is
original 68000 code generated by `tests/amiga/uae4arm/aga_fetch_fixture.py`;
it contains no Kickstart or game code. NanoMig's
[AGA test ROM](https://github.com/MiSTle-Dev/NanoMig/blob/5eea8461bf29069e691af827f77f25fea01df7c4/sim/test_rom/aga_test.s)
inspired its wide-fetch/stripe approach. See [FPGA references](FPGA-REFERENCES.md).

## What is checked

- Eight low-resolution bitplanes and all 256 palette indices across eight banks.
- Four FMODE values: 16-bit, both 32-bit variants and 64-bit fetching.
- PAL and NTSC, with 192 active diagnostic rows in each.
- A pattern that changes each row, exposing incorrect pointer/modulo progression.
- Every one of 122,880 RGB565 pixels in the final 640-wide internal capture, calculated
  directly from column, row and palette index outside UAE.

The checker locates the first complete row and then demands contiguous exact
rows; it cannot shift, crop or rescale individual rows to obtain a pass. It does
not validate the absolute vertical display position. PAL starts at capture row
0 and NTSC at row 23 in this build. The image uses 320 logical low-resolution
pixels doubled to the player's 640-pixel internal buffer.

DDFSTRT/STOP stay at $38/$d0. The completed fetch sequences consume 40, 44, 44
and 48 bytes per stored 40-byte row, so BPL1MOD/BPL2MOD are 0, -4, -4 and -8.
The initial diagnostic incorrectly used zero modulo in the 32-bit cases; the
checker rejected row 1. Correcting the fixture, rather than the expected pixels
or emulator, resolved this. Another fixture construction error (DIWHIGH HSTOP
bit 8) was caught before the matrix. Both are documented in the work log.

## ARM instruction-model results

All eight valid configurations pass, running the installed build's ARM ELF for
16 guest frames each. A ninth ROM deliberately uses the wrong modulo and is
rejected at row 1. Altering individual captured pixels also makes the oracle
fail. These negative controls show that unchanged-build agreement is not the
acceptance criterion.

PAL output SHA256: `f5de89a9141a20eb650fbedc2bde4007553387a0f5aafc303611a39f0e0247ae`.
NTSC output SHA256: `ec7c4260c6e3c414aea93c4d448affd8abd50e37cdde2ddb61486dc4d217d05d`.
All four modes within each standard produce the same expected image.

## Physical A4000TX validation

All eight configurations pass on the physical A4000TX: 960 guest frames total.
Each run uses the installed A1200 interpreter player, audio off and 120 guest
frames, with the same generated ROM. Final captures match the independently
calculated pixels and the corresponding ARM-model capture byte for byte.

| Standard | FMODE 0 | FMODE 1 | FMODE 2 | FMODE 3 |
|---|---|---|---|---|
| PAL | PASS | PASS | PASS | PASS |
| NTSC | PASS | PASS | PASS | PASS |

All runs report zero register mismatches and cache-witness failures, no display
failures, and owned-memory release. The temporary ROM is removed and Core1 is
free. Installed A1200 and FPU player checksums remain unchanged. No speed gain
is claimed and no version or release was changed.

![PAL diagnostic captured from the A4000TX ARM player](aga-oracle/aga-pal.png)

The diagnostic intentionally fills 192 active rows; the remaining area is black.
The existing DF0 image is staged by the host but the diagnostic does not access
it. No disk writes, production player replacement or firmware change is needed.

## Limits

This is a static eight-plane fetch/palette/modulo test. It does not establish
mid-line Copper/DMA transition accuracy, HAM8, dual playfields, sprites,
interlace, super-high-resolution output or full 24-bit palette precision. Individual bitplane bytes in this stripe pattern are either $00 or $ff, so
within-byte bit ordering needs a different fixture. The pattern uses 4-bit
colour components and checks the RGB565 guest capture, not
an HDMI acquisition. Audio quality and performance gains are not measured.

## Reproduce

```sh
.tools/dosbox-model-venv/bin/python tests/amiga/uae4arm/check_aga_fetch.py \
  /path/to/uae-machine.elf .context/amiga/uae4arm/aga-fetch-check
```

Use an A1200-capable ELF with the 32 MiB cache configuration. Tests run serially
because the existing machine harness shares its final capture filename.
The ROM generator can also create a standalone 512 KiB diagnostic image.
