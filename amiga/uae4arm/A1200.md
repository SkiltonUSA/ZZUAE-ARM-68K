# Experimental A1200 and disk storage

Select **A1200**, then **PAL** or **NTSC**. The profile uses a 68020, AGA and
2 MiB Chip RAM. Start with the 68020 interpreter; the existing JIT remains
experimental. Cyclone is a 68000 core and cannot run this profile.
CPU timing follows upstream's 14 MHz A1200 setting. This sets the CPU/chipset
clock ratio; it does not guarantee real-time emulation on the host.

Use a complete 512 KiB A1200 ROM, not separate physical-chip halves. Supported
revisions are 39.106, 40.68 and 46.143. The ROM checksum and revision are checked
before starting the ARM. Version matching alone cannot prove that an unknown
custom ROM belongs to the right machine.

Kickstart 3.1.4 needs compatible disk-based libraries. An old Workbench disk can
reach the shell but stop at a request for `LIBS:workbench.library`. Supply the
matching Workbench installation; this is not fixed by renaming the ROM.

## SD, USB and HDF images

1. Mount the SD card or USB storage in AmigaOS so it appears in Workbench.
2. Choose **Hard disk (.hdf) → Mount…** and select an RDB hard-disk image from that volume or a
   local drive. The current limit is below 2 GiB, with 512-byte sectors.
3. Eject DF0 when booting only from the HDF, or select a Workbench installer ADF.
4. Choose **Save to image** for persistent writes, or **Read only** for testing.

The emulator exposes a Gayle IDE disk to the guest. The real Amiga filesystem
opens the HDF and services block requests. The whole image is not loaded into
ARM RAM, and saving does not copy the whole image. A600 can use this IDE path too.
Raw partition-only HDFs, raw physical-card passthrough, PCMCIA and host-directory
filesystems are not yet supported. An ISO or LHA is not an HDF.

**Do not mount one image in Workbench and the emulator simultaneously.** Close
the guest before removing its SD/USB storage. Image directories must be writable
for session markers, including when the emulated disk is read-only.

## Saving and recovery

`Temporary writes` changes the private floppy copy only. `Save to image` commits
ADF and HDF changes to their files. This is guest file/disk saving, not emulator
save-state slots.

For each write, the host records the old affected 4 KiB blocks in an undo journal,
flushes and verifies that journal, writes and verifies the changed range, then
retires the journal. Interrupted writes are recovered before the next writable
mount. The implementation reuses ZZ8-Bit's journal format and recovery code.
Journal sidecars must stay with the image until recovery finishes. Recovery
restores an interrupted write; it is not a backup against unrelated corruption.

## Joysticks

`Gameport 2` reads a native controller through `lowlevel.library`. `USB / lowlevel
port 2` uses the same interface for a USB pad mapped by Poseidon's HID class.
Configure the HID mapping to joystick port 2 and check the launcher tester.
This does not pair Bluetooth controllers or install USB drivers.

## Development checks

The ARM instruction-model tests exercise the actual Gayle/ATA functions,
two-sector reads and writes, readback, and error reporting when writes are denied.
Native sanitizer tests cover changed-block journalling, interrupted-write recovery
and image boundaries. The optional NEON bitplane and 320-pixel RTG converters
pass instruction-model and physical AGA checks. The experimental A1200 player now uses both plus tested inline Chip RAM reads
in the main 68020 interpreter. Scalar conversion remains available when NEON
is unavailable. See the
[game performance investigation](records/a1200/PERFORMANCE.md) for matched results.

Physical tests have verified PAL and NTSC 256-colour fixtures, complete Core1
restoration and persistent guest creation of `AGATest.txt` in a disposable HDF.
Workbench 3.1 booted from an RDB HDF without an inserted floppy. Alien Breed 3D
and Alfred Chicken reached their startup/trainer screens with both ADFs attached;
these are boot checks, not gameplay acceptance. The standalone Slam Tilt demo
reached its pinball table in a separate navigation run. The WHDLoad installation
of the full game reached
WHDLoad 20.1 but reported shadow-memory allocation failures in the 2 MiB guest.
The profile currently has no emulated Fast RAM; host RAM is not automatically
available as guest Fast RAM.

The CPU-clock regression test checks the actual ARM interpreter's instruction
cost. A register-heavy A1200 fixture also matched JIT/interpreter CPU registers,
condition codes, Chip RAM and pixels. Native-VFP FPU fixtures pass on the same
recorded core build. These instruction-model checks do not replace hardware tests.

These checks do not establish full AGA compatibility or sustained game FPS.
Full interlaced/super-high-resolution output and wider game testing remain pending.
